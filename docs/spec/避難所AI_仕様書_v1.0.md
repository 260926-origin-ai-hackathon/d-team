# 避難所AI 仕様書（v1.0・実装版）

作成: 2026-09-25 02:00（中村・Claude）／v1.1 追記: 2026-09-25 08:00（実機で試した結果の反映。§19）
対象: 防災ローカルAIの**避難所側**（避難所PC1台＋ネット無しWi-Fi）。個人側（避難者のスマホアプリ）は別途。本書はその**接点（QRの中身とHTTP API）だけ**を定義する。

## 1. 一言で

> 避難所のPC1台が、ネットが無くても **受付・名簿・お知らせ・多言語の相談窓口・運営者の助手** を動かす。避難者はPCが出す Wi-Fi に入り、スマホのブラウザで使う。個人情報はPCの外に出ない。ネットが戻ったら名簿と集計を本部へ渡す。

## 3. スコープ

### 3.1 MVP（今日 16:00 までに動かす）
1. **避難所ホットスポット**: PCが親機。入口QR（URL）を印刷できる
2. **受付**: 手入力フォーム／アプリのQRをPCカメラで読む。二重登録の検出。退所
3. **名簿**: 一覧・検索・編集・標準様式順の CSV 出力
4. **運営ダッシュボード**: 人数・世帯数・性別・要配慮者の内訳・不足物資の目安・最新のお知らせ
5. **お知らせ**: 運営者が日本語で投稿 → 英訳を自動生成（編集可）→ 避難者ページに時刻付きで表示
6. **避難者向けAI**: スマホから日本語／英語で相談。お知らせ・避難所情報・FAQ を根拠に答える。ストリーミング表示
7. **運営者向けAI**: 運営マニュアルを根拠にした質問応答（RAG）／要配慮者の洗い出し／不足物資の見積もり
8. **復旧時の同期**: 「ネット復旧」ボタンで名簿 CSV と EEI 集計 JSON を作り、設定した送り先（既定はファイル）へ送る。送信ログを画面に出す

### 3.2 余裕があれば
- 掲示文の生成（決定事項 → 掲示文・館内放送原稿・英語・やさしい日本語）
- 引継ぎ要約（お知らせと対応ログから「昨日までの経緯」）
- 匿名相談の傾向集計（質問ログを匿名で集計し、運営会議用に表示）
- Wi-Fi 2系統（避難者用／運営者用）
- 紙の名簿を写真で読む（qwen3.5:4b の画像入力）

### 3.3 今回作らない
- BLE 受付、デジタル庁アプリとの実連携、マイナンバーカードの読み取り
- 本部側の画面（Supabase 等の実サーバー。送り先アダプタの口だけ用意）
- 都島区以外の地域データ、避難所選択・経路案内（個人側の機能）
- ユーザー別のアカウント、監査ログ、ディスク暗号化の自動化（運用手順に書くだけ）

## 4. 全体構成

```
[避難者のスマホ]                      [避難所PC (Windows)]
 アプリ ──QR表示──▶ PCカメラ ─┐        ┌──────────────────────────┐
 ブラウザ ─Wi-Fi(HTTP)─────────┼──────▶│ FastAPI :8000 (0.0.0.0)   │
                               │        │  ├ 避難者ページ /         │
[運営者 (PC本体のブラウザ)]     │        │  ├ 運営者画面 /staff (PIN)│
 http://localhost:8000/staff ──┘        │  ├ API /api/*             │
                                        │  └ 同期 shelter.sync      │──(復旧時)──▶ 本部
                                        │       │            │        │   (ファイル/HTTP/Supabase)
                                        │  SQLite shelter.db  Ollama :11434 (localhost のみ)
                                        │                     ├ qwen3:1.7b   (チャット・生成)
                                        │                     └ bge-m3       (埋め込み)
                                        └──────────────────────────┘
```

- **AI も個人情報も PC の中で完結**する。Ollama は `localhost` にだけ待ち受け、Wi-Fi 側には FastAPI だけを出す
- 外部 CDN は使わない。JS・CSS・フォントはすべて `shelter/static/` に同梱する（ネット無しで動く条件）
- 受付カメラは **PC本体のブラウザで `http://localhost:8000/staff/checkin` を開く**（ブラウザのカメラは localhost か HTTPS でしか使えない）

### 4.1 技術スタック

| 部品 | 技術 | 備考 |
|---|---|---|
| Web | Python 3.10+ / FastAPI / Uvicorn / Jinja2 | 1プロセス。`--host 0.0.0.0 --port 8000` |
| LLM | Ollama `qwen3:1.7b`（`think=False`, `num_ctx` 8192）。GPU がある PC は `qwen3.5:4b` も可 | `shelter/llm.py` が `ollama` パッケージを直接呼ぶ（接続先は `localai` の設定）。qwen3.5 系は CPU だと前置きを毎回読み直して遅い（§19 v1.1）。デモ用の Gemini 切り替えは [docs/dev/gemini_backend.md](../dev/gemini_backend.md)（未実装） |
| 埋め込み | Ollama `bge-m3`（567M・1.2GB・100言語超・8K文脈） | 軽くするなら `embeddinggemma`（300M・622MB・2K文脈） |
| DB | SQLite（`shelter/data/shelter.db`）。WAL モード | ベクトルも BLOB(float32) で同居 |
| 類似度 | numpy（全チャンクを読み込んでコサイン） | 数千チャンクまで十分 |
| QR 読み取り | ブラウザ `getUserMedia` ＋ jsQR（同梱） | PC 側に Python の画像処理は不要 |
| QR 生成（入口） | `qrcode[pil]` | 印刷用 PNG |
| フロント | Jinja2 テンプレート＋素の JS（`fetch`, `EventSource`） | ビルド無し |
| セッション | PIN 検証後に HMAC 署名付き Cookie | `itsdangerous` |
| ホットスポット | Windows モバイルホットスポット（既定ゲートウェイ 192.168.137.1） | **PC の Wi-Fi を使い、共有元のネット接続が無いと ON にできない**（2026-09-25 確認）。ネット無しはトラベルルーター／テザリング（§5） |

## 5. ネットワークとホスト設定

| 項目 | 値 |
|---|---|
| SSID / パスワード | `HINANJO-AI` / 8文字以上（設定画面で任意。入口QRとポスターに印字） |
| PC のアドレス | `192.168.137.1`（Windows モバイルホットスポットの既定。変わった場合は `ipconfig` で確認し `.env` の `SHELTER_HOST_IP` に書く）。Windows のモバイルホットスポットは、つないでいる端末が無いと数分で**自動 OFF** になる（省電力）。設定 → モバイルホットスポットの「省電力」を OFF にしておく（2026-09-25・検証中に OFF になり 53/80 番の待ち受けに失敗した） |
| 避難者の入口 | `http://192.168.137.1:8000/`（入口QR＝この URL） |
| 入口の案内 | 入口ポスターは **① Wi-Fi の QR → ② ページの QR の 2 枚**（v1.5）。接続時の自動表示（キャプティブポータル・`shelter/captive.py`）は試験機能として残し**既定 OFF**（`SHELTER_CAPTIVE=1` で有効。PC の IP の 53 番〈DNS・全部 PC の IP〉と 80 番〈入口へ 302〉を待つ。ICS の DNS 中継は 0.0.0.0:53 なので PC の IP:53 に bind すると優先される。UDP 53・TCP 80 の受信許可が要る）。OFF にした理由: iPhone で接続確認の横取りまでは届いたが、自動で開くかは機種・設定で揃わず（Android は通知だけの機種が多い・モバイルデータ優先・プライベート DNS や VPN で素通り）、サインイン画面は Safari と保存領域が別になりうる（自己登録の端末 ID・クッキーが別人扱いになるおそれ・未確認） |
| 運営者の入口 | PC 本体で `http://localhost:8000/staff` |
| ファイアウォール | 受信 TCP 8000 を許可（管理者 PowerShell）: `netsh advfirewall firewall add rule name="ShelterAI 8000" dir=in action=allow protocol=TCP localport=8000` |
| Ollama | `OLLAMA_HOST` は既定（127.0.0.1:11434）のまま。Wi-Fi に出さない |
| スマホ側の注意 | 自動表示が効けば Wi-Fi に入るだけで「サインイン」画面に避難所ページが出る。出ない・閉じたときのために、ネット無しの Wi-Fi で「接続を維持しますか」と聞かれたら **「このまま接続」**、URL はブラウザのアドレス欄に直接（検索窓だと失敗）、をポスターに書く |

代替（ホットスポットがネット無しで起動しない場合）: トラベルルーター（PC を有線または Wi-Fi で接続し、ルーターの DHCP で PC に固定 IP）／Android テザリング（PC がクライアントになる。PC の IP を `.env` に書く）。どちらでもアプリ側は「入口QRの URL を開く」だけなので変更無し。

## 6. 個人側アプリとの契約

### 6.1 受付 QR のペイロード
アプリが画面に出し、避難所PCのカメラが読む。**BLE 版（v0.3）と同じ JSON をそのまま使う**。

```json
{
  "v": 1,
  "fmt": "hinanjo-checkin",
  "dev": "a3f9c2e1b7d04c58",
  "name": "山田 太郎",
  "kana": "やまだ たろう",
  "addr": "大阪市都島区東野田町1-2-3-405",
  "sex": "M",
  "dob": "1958-04-02",
  "hh": 3,
  "care": ["ILL", "MED"],
  "alg": [],
  "note": "高血圧の薬を毎朝",
  "lang": "ja",
  "pet": 0
}
```

| キー | 型 | 必須 | 意味（標準様式との対応） |
|---|---|---|---|
| `v` | int | ○ | ペイロードの版。今は `1` |
| `fmt` | str | ○ | `"hinanjo-checkin"` 固定。別形式を将来足すための識別子 |
| `dev` | str | ○ | 端末固有の乱数 ID（16 hex 以上）。**二重登録のキー**。個人番号ではない |
| `name` / `kana` | str | ○ / △ | 氏名 / ふりがな |
| `addr` | str | ○ | 住所 |
| `sex` | `"M"`/`"F"`/`"X"` | ○ | 性別（`X`＝回答しない・その他） |
| `dob` | `YYYY-MM-DD` | △ | 生年月日（年齢計算に使う。無ければ `age` を代用可） |
| `hh` | int | △ | 同行の世帯人数（本人を含む）。既定 1。`members` があれば「1＋同行者の数」より小さくしない |
| `members` | object[] | △ | 同行者（家族）を1人ずつ（v1.6）。`{"name", "kana", "rel", "sex", "dob" または "age", "care", "alg"}`。`rel` は続柄（`spouse` `child` `parent` `grandparent` `grandchild` `sibling` `relative` `other`）。名前の無い要素は無視。29 人まで。受付番号は代表者と同じ |
| `care` | str[] | △ | 要配慮の区分コード。`ILL` 病気・けが / `PRG` 妊産婦 / `INF` 乳幼児同伴 / `DIS` 障がい / `NUR` 要介護 / `MED` 医療機器（透析・酸素等）/ `ALG` アレルギー |
| `alg` | str[] | △ | アレルギーの内訳（`egg` `milk` `wheat` `peanut` `soba` `shrimp` `crab` `other`） |
| `note` | str | △ | 自由記述。**80文字まで** |
| `lang` | str | △ | 使う言語（`ja` `en` …）。標準様式に無い拡張項目 |
| `pet` | int | △ | 同行ペットの数。拡張項目 |

- 文字コード UTF-8、そのまま JSON 文字列を QR に入れる（誤り訂正レベル M）。300〜400 バイト程度なので圧縮不要
- 600 バイトを超える場合だけ、`z:` ＋ base64url(deflate(JSON)) にする。PC 側は先頭 `z:` で判定して両方読む
- **提示すること自体を同意とみなす**（要配慮情報は本人が任意で入れる）。アプリは受付のときだけ QR を出し、ボタンで消す（撮影対策）
- 同じペイロードを **手入力フォームの JSON** にも使う（受付 API は同じ）

### 6.2 HTTP API（アプリやブラウザが Wi-Fi 経由で叩く）
ベース URL: `http://192.168.137.1:8000`。すべて JSON。認証無しの API は避難所 Wi-Fi 内からしか届かない前提。

| メソッド / パス | 認証 | 用途 | 入出力 |
|---|---|---|---|
| `GET /api/health` | 無 | 生存確認・モデルのウォーム状態 | `{ok, model, embed_model, warm, queue}` |
| `GET /api/shelter` | 無 | 避難所の基本情報 | `{name, address, lang:[...], updated_at, rules:[...], facilities:{...}}` |
| `GET /api/notices?lang=ja` | 無 | お知らせ一覧（新しい順） | `[{id, lang, title, body, posted_at, category}]` |
| `POST /api/chat` | 無 | 避難者向けチャット（**SSE ストリーミング**） | 入力 `{session, lang, message, history:[{role,content}]}` → `text/event-stream`。`data: {"delta": "..."}` を流し、最後に `data: {"done": true, "sources":[{"type":"notice","id":3,"posted_at":"..."}]}` |
| `POST /api/checkin` | 無（QR・手入力とも受付端末から） | 受付 | 入力 `{source:"qr"|"manual", payload:<§6.1>, staff_note?}` → `{id, status:"created"|"duplicate"|"updated", evacuee:{...}}`。`dev` が一致すれば `duplicate`（再入所なら `updated`） |
| `POST /api/checkout/{id}` | PIN | 退所 | `{id, checked_out_at}` |
| `GET /staff/export/roster.csv` | PIN | 名簿 CSV（標準様式順） | CSV（UTF-8 BOM 付き。Excel で開ける） |
| `GET /staff/export/eei.json` | PIN | 集計（EEI「避難所等」準拠） | §8.3 |
| `POST /staff/sync` | PIN | 復旧時の同期を実行 | `{transport, sent:[...], log_id}` |

- アプリは MVP では `checkin` を叩かない（QR を出すだけ）。**将来** Wi-Fi 経由の自己受付を足すときは同じ `POST /api/checkin` に `source:"app"` で送る
- CORS: `*` を許可（閉じた Wi-Fi 内。アプリの WebView から叩けるように）
- エラーは `{error:{code, message}}`。`400` 形式不正、`401` PIN、`409` 重複（`checkin` は 409 ではなく `status:"duplicate"` で 200 を返す）

## 7. 画面

### 7.1 避難者向け（スマホ・`/`）
言語切替（日本語／English）は右上。Cookie に保存。文字は大きめ（高齢者）。1画面1目的。

| パス | 内容 |
|---|---|
| `/` | 避難所名・「いま何時のお知らせまで反映」・3ボタン（お知らせ／相談する／避難所の案内）。**はじめての端末は `/register`（自己登録）へ飛ばす**（v1.6。受付画面を一度出した端末・登録済み・運営者の PC はトップ）。未登録なら下に「まだ受付していない方へ」 |
| `/register` | 自己登録。本人の情報に加えて**同行者（家族）を全員**「＋ 同行者を追加」で1人ずつ登録（名前・続柄・性別・年齢・要配慮・アレルギー）。「あとで登録する」でトップへ |
| `/notices` | お知らせ一覧（投稿時刻・カテゴリ: 配給／給水／医療／トイレ／その他） |
| `/chat` | 相談チャット。「AIの回答は参考です。最終判断は受付へ」を常時表示。待っている間は「順番待ち: 前に n 人」→「考えています…」→「答えを書いています…」。回答の下に根拠（お知らせの時刻など）。質問例ボタン（薬が無い／次の配給は／トイレはどこ／充電したい／体調が悪い） |
| `/info` | 避難所のルール・設備・相談先（静的。`shelter/data/shelter_info.ja.md` / `.en.md`） |
| `/tell` | **避難所に伝える**（v1.8・`shelter/cases.py`）。登録済みの端末だけ（未登録は `/register` へ。匿名は受けない）。用件 8 種から 1 つ・「急ぐ」・くわしく（任意・200 字）。AI は通さない。暴力・急病の言葉は窓口の案内を出してレベル 3。**同じ用件をもう一度送ると新規にせず**、未対応ならその案件の本文を最新に、対応済みなら受付済に戻す（再オープン） |
| `/me` | 本人の受付番号・バーコードに加え、**「伝えたこと」の一覧と状態**（受付済／対応中／保留／対応済。v1.8） |

### 7.2 運営者向け（PC 本体・`/staff`・PIN）
| パス | 内容 |
|---|---|


## 9. AI の設計

### 9.1 共通
- AI の呼び出しは `shelter/llm.py` の `stream()`（生成）と `embed()`（埋め込み）の2か所だけ。`temperature 0.2`、`num_ctx 8192`、`think=False`（モデル内蔵の思考は使わない）、回答上限 300 トークン（避難者向け）／600（運営者向け）
- **考えてから生成する**（v1.2）: `stream()` に `llm.Plan` を渡すと、同じ順番（ロック）の中で「短い考え（上限 80 トークン）→ 答え」の2段階で生成する。考えは画面に出さず、段階の切り替わりを SSE の `{"phase": "think"|"write"}` で知らせる。避難者チャットが使う（§9.2 の 4）
- **直列**: Ollama 呼び出しは `asyncio.Lock` で1本にする。待ち人数を `/api/health` の `queue` と画面に出す
- 起動時にウォームアップ（1問投げる）。`keep_alive` を長め（`-1`）にしてモデルをメモリに留める
- 言語: ユーザーの選択言語で答える（プロンプトに `Answer in English.` 等を明示）
- **クラウド AI（Gemini）への切り替え（任意）**: `.env` に `GEMINI_API_KEY` があるときだけ、避難者チャットと運営 AI 助手の右上にスイッチが出る。リクエストごとに `backend: "local" | "gemini"` を送る（状態は端末の localStorage）。根拠（お知らせ・案内・FAQ・マニュアル RAG）の組み立てはローカルと同じで、生成だけを Gemini に回す（避難者チャットの「考え → 答え」の2段階も同じ）。Gemini は直列化しない（順番待ちなし）。失敗してもローカルへ自動で戻さずエラーを返す
- **名簿を使う「要配慮者の洗い出し」は、スイッチに関係なく常にローカル**。埋め込み（bge-m3）・お知らせの英訳・起動時ウォームアップもローカル固定

### 9.2 避難者向けチャット
v1.1 で「資料を丸ごと渡す」から「根拠を選んで渡す」に変えた（小さいモデルが資料から外れた答えを作ったため。§19）。流れ:

1. **ガード**: 性被害・DV・暴力・命に関わる急病はキーワードで判定し、AI を通さず決まった案内を返す（リサーチの制約）
2. **根拠探し**（`shelter/evidence.py`）: 避難所の案内の箇条書き・FAQ の1問1答・最新のお知らせを1行ずつの「根拠」にし、`bge-m3` の類似度＋質問の言葉（漢字・カタカナ・英数字）がそのまま書いてある行への加点で並べる
3. **FAQ そのまま**: FAQ の質問とほぼ同じ（類似度 0.77 以上）で、近いお知らせが無ければ、**AI を通さず FAQ の答えを返す**（約3秒・書いたとおり）
4. **考えてから答える**（`llm.Plan`・v1.2）: それ以外は根拠4行だけを渡す。質問に近いお知らせ（最大2件）は先頭に必ず入れる（「お知らせに出します」とだけ書いた FAQ に押し出されないように）。AI は PC の中で2段階で動く:
   1. **考える**: 「使う根拠: 番号（無ければ「なし」）／要点: 1行」の2行だけを書かせる（画面には出さない。`chat_logs` に `role='plan'` で残す）
   2. **PC 側で確かめる**（`ai_evacuee.think`）: 「なし」なら**生成せずに**「その情報はまだありません」を返す（速く・確実に）。番号があるのに根拠にあるお知らせを外していたら、お知らせを足して考えを「使う根拠: [番号]」だけに書き直す（小さいモデルは質問と同じ文の FAQ「お知らせに出します」を選びがちなため）
   3. **書く**: その考えを会話に足して「答えを書いてください」と頼み、答えだけを1〜3文で書かせる。前置き〜根拠が1段階目と同じなので Ollama が読み直さず、2段階目の追加コストは小さい。選ばれた根拠だけを後処理と出典に使う
   スマホには「考えています…」→「答えを書いています…」と段階を出す
5. **後処理**（`ai_evacuee.clean_answer`）: 根拠の書き写し（「根拠: … 答え: …」）・`[1]` などの番号・根拠に無いお知らせの引用を消す。「その情報はまだありません」が混ざったらその文だけにする。このため避難者チャットは少しずつ流さず、全文を1回で送る
6. **出典**: 渡したお知らせを画面の「出典」に出す（AI に書かせない）

システムプロンプト（要旨・毎回同じにして Ollama の前置きキャッシュを効かせる。根拠と時刻は最後の質問と一緒に渡す）:
- あなたは○○避難所の案内係。**「根拠」の行に書いてあることだけ**で答える。言葉・場所・時刻・数字はそのまま使う
- 根拠に答えが無いときは「その情報はまだありません。受付（運営本部）で確認してください」とだけ答える
- 「お知らせ」で始まる根拠は一番新しい情報。答えが書いてあれば優先する。根拠に無いお知らせや時刻を作らない
- 医療の判断はしない。体調の相談は救護スペースへ案内し、緊急なら大声で人を呼ぶよう伝える
- 氏名・住所などの個人情報を聞かない。1〜3文で短くやさしい言葉で

起動時に根拠の埋め込みと日英の前置きを先に作る（`ai_evacuee.prime_cache`。CPU で約1分）。しきい値は `scripts/check_evidence.py`、答えは `scripts/check_chat.py` で確かめる。

## 10. 同期・エクスポート（拡張性のある設計）

```python
class Transport(Protocol):
    name: str
    def send(self, kind: str, filename: str, content: bytes, meta: dict) -> SendResult: ...

FileTransport     # 既定。shelter/outbox/<日時>/roster.csv, eei.json に書く。USB 持ち出しにもなる
HttpTransport     # SYNC_URL に multipart POST。Authorization: Bearer SYNC_TOKEN。本部が何であれ受けられる
SupabaseTransport # 将来。SUPABASE_URL/KEY で REST upsert（roster→evacuees, eei→shelter_reports）。今回はスタブ
```

- 送るものは常に **同じ2ファイル**（名簿 CSV・EEI JSON）。送り先が増えても生成側は変えない
- `.env`: `SYNC_TRANSPORT=file|http|supabase`, `SYNC_URL`, `SYNC_TOKEN`
- 「ネット復旧」判定は今回 **手動ボタン**。将来は定期的に `SYNC_URL` へ到達確認して自動送信
- 送信ごとに `sync_log` に残し、画面に出す。失敗しても outbox にファイルは残る
- 名簿（個人情報）を送る先は「本部＝市町村の災害対策本部」に限る。国（SOBO-WEB）へ上がるのは集計値だけ、という国の設計に合わせる

## 11. セキュリティ・プライバシー
- 個人情報と AI 処理は PC の外に出ない。ネット復旧時の送信だけが例外（HTTPS・トークン）
- 例外: 運営者・避難者がスイッチでクラウド AI（Gemini）を選んだときは、質問文と根拠（お知らせ・案内・マニュアル抜粋・集計）が Google に送られる。名簿（氏名・メモ）は送らない（要配慮者タスクは常にローカル）
- Ollama は localhost のみ。FastAPI は Wi-Fi 内のみ。運営者画面は PIN＋署名 Cookie（有効 12 時間）
- チャットログは匿名（端末の乱数セッションのみ）。氏名等を AI に聞かせない
- 受付 QR は提示＝同意。要配慮情報は任意項目。アプリ側は受付のときだけ表示
- 二重登録キー `dev` は端末の乱数。個人番号は取得しない
- 運用: 避難所PCは BitLocker を有効にし、離席時はロック。名簿 CSV は outbox から持ち出したら削除
- 避難者データの管理者は避難所を開設する市町村。本システムは委託先のツール（v0.3 と同じ位置づけ）
