## 3. スコープ

### 3.1 MVP（今日 16:00 までに動かす）
1. **初回登録**: 氏名・ふりがな・住所・性別（必須）／生年月日・世帯人数・住まいの種類（マンションの階など）・要配慮・アレルギー・言語・ペット・伝えたいこと（任意）。端末内だけに保存
2. **事前ダウンロードと保持確認**: SLM（約 1.1GB）と地域データを Wi-Fi 接続時に取得。起動のたびに「モデル・データが端末に残っているか」「更新日」を表示。消えていたら取り直しを促す。保存領域の永続化を要求
3. **初動カード**: 初期設定の完了時にテンプレートから作って保存。「今すぐ」「10分以内」「1時間以内」の3段。住まい・世帯構成に合わせて項目を増減。SLM が使えるときは一言の補足を付ける
4. **模擬速報ボタン**: 押すと初動カードが全画面・大きな文字で出て、音が鳴り、読み上げる（対応端末のみ）
5. **最寄りの安全な避難所**: 登録住所（または GPS）から距離を計算し、災害種別で使えない場所を外して上位 3 件。方角矢印（コンパス）・距離・徒歩分数。「開設状況は現地で確認」「最終判断は現地で」を常時表示
6. **AI チャット（出典付き）**: 端末内の防災データ（避難所一覧・ハザード要約・FAQ・応急手当の要点）を検索して SLM に渡し、短く答える。根拠の文書名を回答の下に出す。ストリーミング表示。SLM が動かない端末は**検索モード**（該当箇所をそのまま表示）に自動で落ちる
7. **受付 QR**: 登録内容を避難所仕様 §6.1 の JSON にして QR 表示。ボタンで表示・60 秒で自動的に消す。避難所 PC の `/staff/checkin` で読めることを疎通試験で確認する
8. **避難所につなぐ**: 「避難所のページを開く」ボタン（既定 `http://192.168.137.1:8000/`。入口 QR を読んだ URL に差し替え可）
9. **日英切替**: 画面の文言と AI の回答言語

### 3.2 余裕があれば
- オフライン地図（国土地理院タイルを都島区分だけ事前キャッシュ）に避難所と直線を描く
- 平時の「今日の防災」: 気象庁の警報・注意報 JSON（大阪府）を取って SLM が「あなたの家にとって何を意味するか」を要約（オンライン時）
- 備蓄チェックリスト（毎年開く理由）
- 家族への安否連絡の下書き（SLM）と災害用伝言ダイヤル（171）の案内
- 「やさしい日本語」モード
- 位置情報で地域データを自動切替（他区のデータを追加でダウンロード）
- Android の APK 配布（Capacitor で同じ PWA を包む。避難所 API を http で直接叩けるようになる）

### 3.3 今回作らない
- ネイティブアプリ（Apple Foundation Models / Gemini Nano）、クラウド AI の予備
- 緊急地震速報の実受信・プッシュ通知・自動起動（模擬速報ボタンで代替）
- 経路探索・再ルーティング（v0.3 の「経路モック」も、今回は直線と方角に簡略化）
- 避難所 Wi-Fi 経由の自己受付（`POST /api/checkin` に `source:"app"`）。契約は避難所側にあるので将来足せる
- 都島区以外の地域データ、日英以外の言語
- 音声入力

```
 │   チャット履歴 / 設定                    │ ◀── 取得 ──  Hugging Face（WebLLM のモデル重み）

```

- **AI も個人情報もスマホの中で完結**する。ネットは「アプリ本体・モデル・地域データの取得」と「住所のジオコーディング（初期設定の1回）」にだけ使う
- 避難所 PC とは **QR（人が運ぶ）** と **ブラウザのリンク（避難所ページを開く）** だけでつながる。アプリから避難所 PC への通信は無い
- 外部 CDN を実行時に参照しない。ライブラリはすべてビルドに同梱する（オフライン起動の条件）

## 5. 動作モード

| 状態 | 答える AI | ネットの使い道 | 画面の表示 |
|---|---|---|---|
| ネットあり（平時） | スマホ内 SLM | アプリ・モデル・地域データの取得と更新。住所のジオコーディング（初回） | 「データ更新: 9/25 07:00」 |
| ネットなし（機内モード） | スマホ内 SLM（同じ） | なし | 「オフラインで動作中」 |
| 避難所（ネットなしの Wi-Fi） | スマホ内 SLM。避難所 AI は**ブラウザで避難所ページを開いて**使う | なし（避難所 PC は同じ Wi-Fi 内の別サイト） | 「避難所のページを開く」 |
| WebGPU 無し／メモリ不足／モデル未取得 | **検索モード**: 該当する文書の抜粋をそのまま表示。初動カード・避難所選択・QR はそのまま動く | — | 「この端末では AI が使えません。検索で答えます」 |

**判定**: 起動時に `navigator.gpu` の有無 → WebLLM の `hasModelInCache(modelId)` → `CreateMLCEngine` の初期化成否、の順で見る。失敗したら検索モードに落ち、理由を「データ」画面に出す。

## 6. 避難所側との契約（避難所仕様 §6 を守る）

### 6.1 受付 QR のペイロード
アプリは登録内容から次の JSON を作り、**そのまま UTF-8 の文字列として** QR にする。項目・区分コードは避難所仕様 §6.1 と `shelter/schema/standard_form.py` が正。アプリ側で勝手に増やさない。

```json
{"v":1,"fmt":"hinanjo-checkin","dev":"a3f9c2e1b7d04c58a3f9c2e1b7d04c58",
 "name":"山田 太郎","kana":"やまだ たろう","addr":"大阪市都島区東野田町1-2-3-405",
 "sex":"M","dob":"1958-04-02","hh":3,"care":["ILL","MED"],"alg":[],
 "note":"高血圧の薬を毎朝","lang":"ja","pet":0}
```

- `dev`: 初回起動時に `crypto.getRandomValues` で 16 バイト作り 32 桁の hex にして IndexedDB に保存。**二重登録のキー**なので端末で固定。アプリを消すと変わる（再入所は避難所側が氏名で拾う）
- `care` は `ILL PRG INF DIS NUR MED ALG`、`alg` は `egg milk wheat peanut soba shrimp crab other`。`alg` があるとき `care` に `ALG` を入れる（避難所側でも補うが、アプリでも揃える）
- `note` は 80 文字で切る。`hh` は 1〜30、`pet` は 0〜20
- `JSON.stringify` は空白無し（`separators` 相当）。600 バイトを超えたら `"z:" + base64url(deflate(JSON))`（`pako.deflate`、パディング無し）。避難所側は両方読む
- 表示は「受付 QR」画面を開いたときだけ。**60 秒で自動的に消す**。閉じるボタンあり。画面の明るさを上げる案内を出す
- **提示＝同意**。要配慮情報は任意項目で、登録画面に「避難所の受付にだけ渡します。スマホの外には送りません」と書く

### 6.2 入口 QR と避難所ページ
- 避難所の入口ポスターの QR は `http://192.168.137.1:8000/` の URL。スマホの標準カメラで読めばブラウザが開く。**アプリは介在しなくてよい**
- アプリの「避難所につなぐ」画面は、この URL を `target="_blank"` で開くだけ。URL は設定で変えられる（トラベルルーター構成などで IP が変わる場合）
- `https://` のアプリから `http://192.168.137.1` へ `fetch` すると混在コンテンツで止まる。**避難所 API は MVP で使わない**。将来 Capacitor で包んだときに `source:"app"` の自己受付を足す（避難所仕様 §6.2 の予約済み）

### 6.3 疎通試験（今日やる）
1. 避難所 PC で `scripts\run_shelter.ps1` を起動し、`http://localhost:8000/staff/checkin` を開く
2. アプリの「受付 QR」を PC カメラにかざす → プレビューに氏名・年齢・要配慮が出て「登録」→ 受付番号が出る
3. 同じ QR をもう一度 → `duplicate`（二重登録の検出）
4. 手元で先に確かめるなら、アプリの開発画面で QR の文字列をコピーし、`POST http://localhost:8000/api/checkin/preview` に `{"source":"qr","payload":"<文字列>"}` を送って 200 が返ることを見る
5. 逆方向の確認: `python scripts/make_sample_qr.py` が作る `outputs/sample_checkin_*.json` を Vitest に読み込み、アプリの `encodePayload()` が同じキー・同じ値を出すことを検査する

### 8.2 同梱する地域データ（`app/public/data/miyakojima/`・ビルド時に precache）

| ファイル | 中身 | 作り方 |
|---|---|---|
| `shelters.json` | 都島区の災害時避難所 18・一時避難場所・広域避難場所・津波避難ビル。`{id, name, name_en?, kind, addr, lat, lon, for:['earthquake','tsunami','flood','fire'], hours?, note?}` | `shelter/data/local/miyakojima_shelters.md` を元に `scripts/build_app_data.py` で作る。緯度経度は国土地理院 住所検索 API（`https://msearch.gsi.go.jp/address-search/AddressSearch?q=<住所>`）で 1 件ずつ取り、結果を JSON に**固定して commit**（実行時に叩かない）。例: 東高等学校（東野田町4-15-14）→ 135.528137, 34.70002（2026-09-25 取得） |
| `hazard.ja.md` / `hazard.en.md` | 東野田町周辺の想定浸水深の要約（目安）・警戒レベル・避難の考え方 | `shelter/data/hazard/miyakojima_hazard_summary.md` と `miyakojima_suigai_keihatsu_en.txt` から要点化 |
| `faq.ja.md` / `faq.en.md` | 災害直後〜避難所でよくある質問 | `shelter/data/faq.*.md` を流用 |
| `first_aid.ja.md` | 応急手当の要点 | `shelter/data/manual/first_aid_essentials.ja.md` を流用（英語は SLM が訳す） |
| `card_templates.json` | 初動カードのテンプレート（§10.2） | 本書から起こす |
| `version.json` | `{version:'2026-09-25', region:'osaka-miyakojima'}` | 手で更新 |

- `kind` と `for` の対応: 災害時避難所（津波避難ビル兼）→ 全災害／一時避難場所（公園）→ 地震・火災（津波・水害は不可）／広域避難場所 → 防災マップの記載どおり／学校以外の津波避難ビル → 津波のみ・`hours` に利用可能時間
- 所在地の番地は読み取り誤りがありうる（元データの注記）。「掲示前に原本で確認」の注記を `note` に残す
- 出典と利用条件（大阪市 CC BY 4.0、国土地理院タイル・API の利用規約）は `app/public/data/README.md` に書き、画面の「データ」に出典を出す

### 8.3 検索インデックス
- 起動時に上の md を見出し（`##`）単位 → 300 文字・重なり 50 文字のチャンクに割り、MiniSearch に入れる（数百件・1 秒未満）
- トークナイザ: 英数字は単語、CJK は**文字 2-gram**。`prefix: true`, `fuzzy: 0.1`, `boost: {title: 2}`
- 検索結果は上位 4 チャンク。`{doc, section, text, score}` を返し、チャットの出典表示にそのまま使う

## 9. AI の設計

### 9.1 共通
- `CreateMLCEngine(modelId, { initProgressCallback })` を起動時ではなく**「AI に相談」か「データ」画面を開いたとき**に初期化（初回のロードは数十秒。ホームを速く出す）。以後はシングルトンで保持
- 生成パラメータ: `temperature 0.3`, `max_tokens 200`（電池と速度）。context 4096（プリビルトの既定）に収まるよう、履歴は直近 4 往復、検索チャンクは 4 件
- **Qwen3 の thinking を無効にする**: `chatCompletion` の `extra_body: { enable_thinking: false }`（WebLLM 0.2.85 の `ChatCompletionRequestBase` に定義あり。false のとき空の `<think>

</think>` を先頭に付けて思考トークンを抑える。2026-09-25 ソース確認）。念のため出力に `<think>` が残ったら取り除く
- ストリーミング: `stream: true` で `delta` を画面に流す。中断ボタン（`engine.interruptGenerate()`）
- 言語: プロフィールの `lang` で「日本語で答えてください」「Answer in English.」を system に入れる

### 9.2 モデルの選び方（今日の最初の 1 時間で実機比較）

| 候補（WebLLM プリビルト） | 取得サイズ目安 | VRAM | 見どころ |
|---|---|---|---|
| **`Qwen3-1.7B-q4f16_1-MLC`**（既定） | 約 1.1GB | 2.0GB | 日本語が通る最小クラス。thinking 無効が要る |
| `Qwen3-0.6B-q4f16_1-MLC`（軽量枠） | 約 0.4GB | 1.4GB | 古い端末・iPhone 向け。品質は落ちる |
| `gemma-2-2b-jpn-it-q4f16_1-MLC`（対抗） | 約 1.4GB | 1.9GB | 日本語チューニング済み。Qwen3 の日本語が弱ければこちら |

- 比べ方: 避難所・応急手当・多言語の 15 問（`app/eval/questions.md`）を 2 端末で流し、正答・平均秒数・初回ロード秒数を `docs/app_model_eval.md` に表で残す（ピッチの「技術完成度」用）
- `modelId` は設定で切り替えられる（`settings.modelId`）。既定は端末の `navigator.deviceMemory` が 4 未満なら 0.6B、それ以外は 1.7B

### 9.3 チャットのプロンプト（要旨）
system:
- あなたは大阪市都島区の住民のための防災アシスタント。**渡された資料だけ**を根拠に答える。資料に無いことは「手元の資料にはありません。市の防災情報か避難所の受付で確認してください」と言う
- 短く、やさしい言葉で。箇条書きは 3 つまで。根拠にした資料は文末に `[1]` のように番号で示す
- 医療の判断はしない。命に関わる症状・けがは **119** に電話するよう最初に言う
- 氏名・住所などの個人情報を聞かない
- 性被害・DV・暴力の相談には答えず、相談先（警察 110・女性相談）と「安全な場所へ」だけ案内する

user に付けるもの: `[資料1] 文書名 › 節\n本文` ×4、`【あなたの状況】マンション 5 階・3 人・乳幼児あり`（プロフィールから住まいと世帯構成だけ。氏名・住所は渡さない）、質問文。

### 9.4 初動カードの補足（SLM の唯一の「生成」用途）
- 初期設定の完了時、SLM が使えるときだけ 1 回呼ぶ: 「この世帯（住まい・構成）が地震の直後に特に気をつけることを 2 文で」。結果を `card.aiNote` に保存。使えなければ空のまま（カードは完成している）

### 9.5 検索モード（SLM 無し）
- 質問を MiniSearch にかけ、上位 3 チャンクを「資料の該当箇所」として表示。定型の前置き（「AI は使えないため、資料の該当箇所を表示します」）。119・110 の案内は同じ

## 10. ロジック（LLM を使わない部分）

### 10.1 避難所の選択
```
入力: 現在地 (lat, lon)（GPS 許可があれば GPS、無ければ profile.geo）、災害種別 d
1. shelters.json から for に d を含むものを残す
2. 津波・水害では kind が '一時避難場所' のものを外す。hours があるものは「時間外の可能性」を注意に付ける
3. ハバーサイン距離を計算し昇順に並べる
4. 上位 3 件を返す。徒歩分 = 距離[m] / 80（切り上げ）
5. 方角 = 現在地→避難所の方位角（0°=北）。矢印の回転 = 方位角 − 端末の向き（コンパス）
```
- 現在地が無い（未登録・ジオコーディング失敗）ときは、京橋駅（QUINTBRIDGE）を仮の位置にして「住所未設定」と表示
- ハザードによる除外（v0.3 の「浸水・土砂の想定区域にある避難所を外す」）は、区域ポリゴンが手元に無いため今回は**注意表示に留める**（東野田町の目安浸水深を水害タブに表示）。将来: 国土数値情報の浸水想定区域を同梱して交差判定

### 10.2 初動カードのテンプレート（`card_templates.json`）
災害種別 × 条件で項目を選ぶ。条件は `always` / `apt_high` / `apt_low` / `house` / `withInfant` / `withElderly` / `pet` / `care:MED` / `care:NUR` / `alg`。

| 段 | 項目（地震・抜粋） | 条件 |
|---|---|---|
| 今すぐ | 頭を守る。揺れが収まるまで動かない | always |
| 今すぐ | 火を消す・ブレーカーを落とす前に、まず身の安全 | always |
| 今すぐ | ドアを開けて出口を確保（枠のゆがみで開かなくなる） | apt_high, apt_low |
| 今すぐ | エレベーターは使わない | apt_high |
| 今すぐ | 赤ちゃんを抱えて頭を覆う | withInfant |
| 10分以内 | 靴を履く（ガラス）。家族の安否。火元の確認 | always |
| 10分以内 | 医療機器の電源・予備バッテリーを確認 | care:MED |
| 10分以内 | 薬・お薬手帳を非常持出袋へ | care:ILL, withElderly |
| 10分以内 | ペットをケージに。フード・水 | pet |
| 10分以内 | 津波の恐れがあれば高い所へ（津波避難ビル一覧を見る） | always（都島区は南海トラフで浸水想定あり） |
| 1時間以内 | 建物の損傷を確認。危なければ最寄りの避難所へ（このアプリの「避難所を探す」） | always |
| 1時間以内 | 在宅避難できるなら水・食料・トイレの確保。ガスの元栓 | apt_high, house |
| 1時間以内 | 家族に安否連絡（171・SNS）。避難所に行くなら受付 QR を準備 | always |
| 1時間以内 | 粉ミルク・おむつ・アレルギー対応食を持つ | withInfant, alg |

- 生成は純関数 `buildCard(profile, templates, disaster)`。Vitest で「マンション高層＋乳幼児」「戸建＋要介護」の 2 例を固定値で検査
- 日英の文言はテンプレートに両方持つ（SLM に訳させない）

## 11. オフライン・保存領域

- **Service Worker**（Workbox `generateSW`）: `index.html`・JS・CSS・フォント・`public/data/**` を precache。`navigateFallback: index.html`。**WebLLM のモデル URL（`huggingface.co`, `raw.githubusercontent.com`）は SW で触らない**（WebLLM 自身が Cache API に入れる）
- モデルの有無は `webllm.hasModelInCache(modelId)`。削除は `webllm.deleteModelAllInfoInCache(modelId)`
- 初回起動で `navigator.storage.persist()` を呼び、結果を「データ」画面に出す。iOS Safari は**ホーム画面に追加**しないと 7 日間未使用で消えうる（WebKit の保存ポリシー）→ 案内を出す
- モデル取得は Wi-Fi 推奨。`navigator.connection?.type` が取れる端末では「モバイル回線です。約 1.1GB」と警告
- 更新: `version.json` をオンライン時に取りに行き、差があれば「地域データを更新」ボタンを出す（自動更新はしない。災害時に SW の更新で画面が切り替わるのを避ける）

## 12. セキュリティ・プライバシー
- プロフィール・チャット・初動カードは端末内だけ。送信する仕組みが無い（ジオコーディングの住所文字列だけが国土地理院 API に渡る。初期設定の 1 回・HTTPS。「住所の位置を調べるために国土地理院に送ります」と表示し、拒否したら地図上で位置を指定するか京橋駅を仮位置にする）
- 受付 QR は表示のときだけ・60 秒で消える・提示＝同意（避難所仕様と同じ）
- `dev` は乱数。個人番号やアカウントは持たない。ログインも無い
- 要配慮情報は「要配慮個人情報」。登録画面で任意・同意文・「避難所の受付にだけ渡す」を明記
- 依存ライブラリはビルドに同梱。実行時の外部通信先は GitHub Pages（本体）・Hugging Face（モデル）・国土地理院（初回）だけ。「データ」画面に列挙する

## 18. リスクと逃げ道

| リスク | 逃げ道 |
|---|---|
| Android 実機で WebLLM が動かない・遅い | 0.6B に落とす。それでも駄目なら検索モードで通し、AI は PC の Chrome（デモ機）で見せる |
| Qwen3 の日本語が弱い・`<think>` が漏れる | 出力の除去。駄目なら gemma-2-2b-jpn に切替（設定 1 行） |
| モデルがブラウザから消される | デモ直前に `#/data` で確認。予備端末にも入れておく |
| iPhone で動かない | デモは Android。iPhone は「iOS 26 で対応」と口頭 |
| ジオコーディングが失敗 | 位置を京橋駅に固定（`version.json` に既定座標）。住所は QR にだけ使う |
| コンパスが室内で狂う | 矢印は「目安」。距離と所在地を主に |
| 受付 QR が PC カメラで読めない | `qrcode` の `scale` を上げ、画面の明るさ最大。60 秒の自動消去を 180 秒に延ばす |
| GitHub Pages のデプロイに手間取る | `npm run build` の `dist/` を Cloudflare Pages か Vercel にドラッグ＆ドロップ |
| 混在コンテンツで避難所ページが開かない | ページ遷移（リンク）は混在コンテンツの対象外。`fetch` はしない設計なので問題なし。駄目ならスマホのカメラで入口 QR |
