避難所AI — サービス概要（自治体向け・2026-09-25）

避難所側だけを切り出した1枚。保管庫（仕様書 v1.0・避難所運営リサーチ・メンタリング・実装ログ）の内容から起こした。 数字の多くはリサーチ（Claude が一次資料から抽出・人間の原文照合は未実施）なので、外に出す前に出典を当たること。

1. 一言で

ネットも国のシステムも止まっている最初の1〜3週間、避難所のPC1台で「受付・名簿・お知らせ・多言語の相談窓口・運営者の助手」を動かす。個人情報は避難所の外に出さず、通信が戻ったら市町村の本部へ名簿と集計を渡す。

主な買い手は市町村（避難所を開設する自治体）。世帯向けアプリは「受付QRを持ち込む入口」として付随する。

2. 自治体が困っていること（リサーチより・⚠️未検証(AI由来)）

現場の事実 出典
職員が桁違いに足りない。益城町は職員約250名に避難者最大16,000人。輪島市は各避難所2名が24時間常駐、1人で5避難所を担当した職員も 益城町検証報告・内閣府 能登避難所運営実態調査
職員自身が被災者。能登の被災自治体職員は時間外 月100〜240時間、「電話対応で一日が終わり、定時後にやっと事務作業」。運営職員の82%が症状を抱えながら勤務 自治労石川・産業医大
時間を奪うのは定型作業: 名簿の手書きと様式変更の二度手間、3時間ごとの状況報告、日報、物資の在庫把握、安否照会、同じ質問への繰り返し回答、交代のたびの引継ぎ デジタル庁実証・内閣府
応援職員は「引継ぎに限界」「職員によって対応方針が異なる」「地域のことが分からない」 総務省・内閣府
困っても言い出せない。要配慮者は「周りに迷惑」で最初の避難所を離れる率が一般の2.5倍。意見箱・相談室を1か月以内に置けた市町は21〜43%、理由は「人員がいない」 内閣府男女共同参画局
通信は1〜3週間止まる（能登: 基地局停波最大839局、復旧まで「3週間近く」）。Starlink 約700台は避難所到達まで約10日 総務省・KDDI
既存の避難所DX（防災DXサービスマップ101件）は受付・名簿・混雑が中心ですべてクラウド前提。職員の本音「電源、電波がないと使い物にならない」「有事にしか使わないシステムは使いこなせない」 デジタル庁 R6 実証
非常用電源は指定避難所の61.1%、学校避難所の77.2%にある。ノートPC1台なら過半の避難所で動く 内閣府・文科省
関連死は直接死の2.3倍（能登）。39.2%に「避難所等生活の負担」が関与、80歳以上が約8割 石川県

国の方針とも合う: 2024年12月のガイドライン改定は「困りごと相談窓口」「引継ぎ体制」を要求。文科省 BRIDGE は防災AIに「RAGで根拠を縛る」「個人情報を外に出さない」を要件化。改正災対法（2025年5月）はデジタル活用を努力義務化。

3. 避難所AIができること（実装済み・2026-09-25 03:00 時点）

避難所PC（Windows ノート1台）が Wi-Fi の親機になり、避難者はスマホのブラウザで開く。アプリ不要。AI（Ollama・qwen3.5:4b）も名簿も PC の中で完結。

誰に 機能 中身
受付担当 受付 世帯アプリの QR を PC カメラで読む／手入力。二重登録の検出、退所。項目は内閣府の避難者カード標準様式（案）に準拠
運営本部 名簿・報告 検索・編集、標準様式順の CSV（J-LIS 被災者支援システムへ職員が取り込む前提）、EEI「避難所等」準拠の集計 JSON
運営本部 ダッシュボード 在所人数・世帯数・性別・乳幼児・要配慮者（区分別）・言語別・ペット・不足物資の目安（水 3L/人/日、簡易トイレ 1基/20人 など 2024 ガイドライン準拠）
運営本部 お知らせ 日本語で投稿 → 英訳を自動生成（編集可）→ 避難者ページに時刻付きで掲示
避難者 相談窓口（日英） スマホから匿名で質問。時刻付きのお知らせ・避難所情報・FAQ だけを根拠に答え、無ければ「受付で確認」。医療判断はしない。暴力・性被害・急病の言葉は AI を通さず 110/119/運営本部/AED の案内を返す
運営者 AI 助手 大阪市「避難所開設・運営ガイドライン」（令和7年3月）・内閣府ガイドライン（令和6年12月）など約19万字を根拠にした質問応答（出典付き）、要配慮者の洗い出し（抽出は SQL・AI は順序と理由の要約だけ）、物資見積、掲示文・館内放送原稿・やさしい日本語の生成、交代時の引継ぎ要約
運営本部 復旧時の同期 「ネット復旧」で名簿 CSV と EEI 集計 JSON を本部へ。送り先はファイル／HTTP／将来 Supabase など差し替え式

実測（本人PC・RTX 4060 Ti）: チャット最初の文字まで約1.5〜2秒、マニュアル RAG 約10秒、同時3人は順番待ちを画面表示。スモークテスト 26/26。未確認: Windows ホットスポットのネット無し起動、実カメラでの QR 読み取り、GPU 無しPCでの速度。

4. 自治体にとっての価値

  1. 職員の定型作業を減らす: 名簿の転記・集計・報告書・掲示文・引継ぎを AI が下書きする。デジタル庁実証では受付デジタル化で入所登録 最大90.2%減、報告書 平均約48%減
  2. 応援職員が初日から回せる: 地域のマニュアルを根拠に「次にやること」を出す。対応方針のぶれを減らす
  3. 要配慮者と外国人を取りこぼさない: 受付時に持病・アレルギー・言語が入り、一覧になる。多言語の相談窓口は人が要らない
  4. 言い出せない人の入口: 匿名で聞ける窓口と、その傾向の匿名集計を運営会議に渡す
  5. 国の仕組みに乗る: 個人データは市町村まで・国には集計値だけ、という国の設計に合わせ、標準様式 CSV と EEI で受け渡す。デジタル庁のマイナンバーカード受付アプリの隣に置く補完（カードに無い要配慮情報を担う）。カードは読まず個人番号も持たない
  6. 個人情報が外に出ない: AI も名簿も避難所PCの中。BRIDGE の要件と同じ
  7. 平時も使える: マニュアル検索・訓練（TTX）で普段から触れる。「有事にしか使わないシステム」問題への答え

価格の参考値 防災情報伝達システム更新 2億、災害対応業務システム 3億、定期更新 年150万。本システムは基幹の上に乗るので安いはず。手応えは「1,000万円以下」（単位・対象は要確認） 調査中

6. 既存との違い

既存 何をしている 避難所AIとの違い
デジタル庁 マイナンバーカード受付アプリ カードで4情報を取り込む受付。オフライン可 受付だけで AI が無い。2026年9月時点で実証1回（名張市）・公開 API 無し。隣に置いて補完
民間の避難所受付（くまもとアプリ・大垣市ポケコム・品川区 LINE 型など） 受付・名簿・混雑のクラウドサービス 通信前提。通信が戻れば併用できる
NTT東×横須賀市 災対本部AI、LINE FAQ ボット 本部支援・制度案内（クラウド LLM） 避難所の端末で完結しない

Starlink・衛星直接通信 つながる手段 到達まで約10日、電源・空・台数・通信量の制約。つながらない間とStarlink が来ない小規模・自主避難所を担う

国内でローカルLLM×避難所の実証は見当たらない（未確認）。海外研究（Pocket RAG・TRIDENT）はオンデバイス SLM＋RAG を「避難所への事前配置」として提案している。

9. 正直なリスク・未決

  • 価格と契約単位が未確定。自治体ヒアリングは未実施（返事待ち）
  • 通信途絶が短い災害では価値が薄い。守りどころは「最初の1〜3週間」と「小規模・自主避難所」
  • 高齢者は端末に近づかない。運営者が端末を持って巡回する・大きな文字・音声など運用設計が要る
  • 不満・苦情や個別判断（全壊判定など）を AI が一次対応すると火種になる。対象外にしている
  • ホットスポットのネット無し起動・実カメラ QR・GPU 無し PC の速度が未確認
