# 避難所AI — 事業展開とマネタイズの選択肢（2026-09-25 リサーチ）

前提: メンターの助言「実証実験 → 補助金・交付金 → 継続利用」の順で語る（[[メンタリングで出た方向性（防災グッズ・避難所サーバー）]]）。本人の見立て「補助金などを用いた実証実験レベルでの導入 → 本格導入」を本線にし、それ以外の入口も並べた。
数字は 2026-09-25 の Web 調査（出典は末尾。同日 07:40 に追加調査で §2・§3・§4・§5 を補強）。制度の年度・上限は変わるので、申請前に一次資料で確認すること。

## 5. 「防災という理念があるから赤字でも続ける」を言い訳にしない設計
メンターの指摘: 「社会に必要だから赤字でも続く」は言い訳に聞こえる。**続く根拠を構造で示す**（[[メンタリングで出た方向性（防災グッズ・避難所サーバー）]]）。

### 5-1. 続ける価値は社会の側で黒字（事業者の赤字と切り分ける）
- 能登の関連死は 520人で直接死 228人の 2.3倍。石川県分 449人の 39.2%に「避難所等生活の負担」が関わり、80歳以上が約8割（[[避難所運営の現状調査（人手不足・言い出せなさ・情報途絶）]]）。避難所の質は関連死の数に直結する
- 参考値: 内閣府の交通事故調査では死亡1人あたりの社会的損失を約 2.26億円（支払意思額法）と試算。災害関連死に同じ物差しを当てれば、**1自治体の年額（数百万円）は関連死1人分の損失の 1/100 以下**。「事業として赤字」でも「社会として黒字」が桁で成り立つ
- 避難所運営は準公共財。民間の売上だけで採算を合わせる前提が間違いで、**「誰が費用を持つか」を設計する話**に置き換える

### 5-2. 潰れない構造（3本の柱）
| 柱 | 中身 | なぜ続くか |
|---|---|---|
| **固定費を極小に** | ローカルAI（クラウド費ゼロ）・公開モデル・公開データ・1人で保守できるコード。ソースは公開（OSS）し、**会社が止まっても避難所PCの中で動き続ける** | 撤退ラインが低い。自治体にとっても「ベンダーが消えても動く」は採用理由 |
| **平時の収入で運転費を賄う** | 訓練（TTX）・研修・マニュアル検索の年額（§4-H）、介護施設・企業BCP（§4-B, C） | 災害が無い年もキャッシュが入る。「有事にしか使わない」問題の答えと同じ |
| **寄附・CSR・成果連動で自治体負担をゼロに近づける** | 下の 5-3 | 自治体が「予算が無い」と言えなくなる |

### 5-3. 寄附・CSR・成果連動の具体的な入口
- **企業版ふるさと納税（地方創生応援税制）**: 自治体の地域再生計画に載った事業へ企業が寄附すると、税額控除と損金算入で**企業負担は約1割**。令和7年度税制改正で**令和10年3月末まで延長**。寄附実績は令和元年度 33.8億円 → 令和5年度 470億円、活用自治体は累計 1,536団体。対象分野に「防災・復興」を含む。→ **「避難所AI導入事業」を自治体の計画に位置づけ、NTT西日本・損保・地元企業が寄附で賄う**形にできる。内閣府の活用事例集には防災・復興分野の寄附事例があるが、**避難所 DX に特化した寄附事例は見つからなかった**（未確認）。災害後の復旧・復興事業は認定手続きが簡略化される制度もある
- **企業の CSR・包括連携協定**: 損保ジャパンは自治体と連携協定を多数締結（例: さいたま市 2026年7月）。通信・電力・鉄道も同様。「避難所の中」を協定メニューに入れてもらう
- **成果連動型（PFS／SIB）**: 「避難所運営の職員時間」「要配慮者の把握率」「関連死ゼロ」を成果指標にした成果連動契約。内閣府に **PFS 推進交付金**（自治体の PFS 導入経費を支援・令和5〜6年度の採択実績あり）と事例集がある。防災分野は日本総研が「地域防災力強化に資する PFS/SIB の可能性」（2025年1月）で検討している段階で、**前例はほぼ無い＝先行できるが、成果指標の測り方を自分たちで設計する必要がある**
- **無償提供→制度化の前例**: 能登の Suica 避難者把握（JR東・Palantir・SOMPO が官民共創で無償提供）、東武トップツアーズの被災者支援AI（無償公開）。有事の無償提供が次の実証・調達につながる

### 5-4. 器（法人形態）の案
- **株式会社＋非営利の二枚**: 商用サポート・SaaS は株式会社、コア（受付 QR の形式・名簿の標準様式・避難所AIのソース）は一般社団法人か OSS 財団で公開。Red Hat 型の「OSS コア＋有償サポート」
- **国の方向とも合う**: デジタル庁は 2025年11月に「オープンソース化・OSS利活用に関する有識者検討会」を始め（目的はベンダーロックインの排除。公開範囲を省庁内／全国自治体／一般の3段階で整理）、2026年4月には政府生成AI「源内」の一部を商用利用可能なライセンスで GitHub 公開した。「自治体向け AI は OSS で重複開発を防ぐ」が国の流れなので、**避難所AIを OSS で出すことは調達上の弱みではなく強みになる**
- ピッチの一言: **「災害のときは無償で動き、平時の訓練と企業の寄附で運転費を賄い、利益は次の自治体への横展開に使う。会社が消えても避難所のPCの中で動き続ける設計にした」**

## 6. 他の自治体向けサービスはどう入り、どう課金しているか
保管庫のリサーチ（`docs/research/04-dx-landscape.md` の先行事例16件・[[避難所運営の現状調査（人手不足・言い出せなさ・情報途絶）]]）と 2026-09-25 の Web 調査から。

### 6-1. 事例
| サービス | 課金の型 | 入り方・広がり方 | 避難所AIへの示唆 |
|---|---|---|---|
| **ポケットサイン防災**（熊本市・宮城県など） | **フリーミアム**: 人口5万人未満は「避難所3か所まで永年無料」、4か所目以降は有料（個別見積）。2025年11月に資金調達 | 自治体公式スーパーアプリに防災を同梱（平時利用がある）。**宮城県内全35市町村**で県単位の面展開、熊本市は171避難所 | 無料枠で入り、県単位で広げる。平時に使う入口を持つ |
| **Spectee Pro**（SNS×AI 危機管理） | SaaS の年額。契約 1,000 超、47都道府県で導入かトライアル | **民間企業の BCP で稼ぎ、自治体には同じ製品**を売る。自治体契約数 No.1 を看板に | 企業 BCP（§4-C）と自治体を同じ製品で取る |
| **Bot Express「GovTech Express」**（LINE 上の行政手続き） | **初期費ゼロの定額サブスク**（機能全部込み。限定パッケージで月 5万円の例）。350自治体超（2026年4月） | 住民が既に持つ LINE に乗る（アプリを入れさせない）。国の制度変更に追加費用なしで追従 | 初期費ゼロ・定額・「入れさせない」は避難所AIと同じ思想 |
| **デジタル庁 避難所 PoC → モデル仕様書** | 国の委託（富士通Japan が開発）→ 令和5〜7年度の実証 | 実証の成果を「避難所運営システムのモデル仕様書」に反映し、自治体が民間製品を調達する形へ。防災DXサービスカタログ・DMP に掲載 | カタログと DMP に載る。モデル仕様書の項目に合わせる |
| **Suica 避難者把握（能登）** | 官民共創で**無償提供**（JR東・Palantir・SOMPO） | 有事の無償提供 → 国の実証・制度化（マイナカード版へ） | 有事の無償提供は次の調達への投資 |
| **SOCDA（防災チャットボット）** | 国の研究費（SIP）→ 自治体実証（神奈川県・三重県）→ LINE 基盤 | 研究費で作り、既存プラットフォームに載せる | 防災庁・BRIDGE の研究費は使える（§4-G） |
| **NTT東日本×横須賀市 災対本部AI** | 通信大手の**包括連携協定の中で実証**（自治体負担なし） | 大手の協定に相乗り | NTT西日本（QUINTBRIDGE）との協定に乗る |
| **らくらく避難所くん（テレネット）・ヴァカン・ゼンリン等** | 価格は問合せ（ヴァカンは初期 40万円〜＋月 9.3万円〜） | 日立等と組んで自治体実証（養父市・豊中市・三田市） | 既存ベンダーは AI を持たない → AI レイヤー提供（§4-F） |
| **GovTech東京 共同調達** | 都内自治体がまとめて入札（AI-OCR・議事録 AI など、2026年度 5案件） | 県・広域で共同調達すると単価が下がり、担当者の手間も減る | 大阪府・関西広域での共同調達を狙う |
| **スタートアップ技術提案評価方式（随意契約）・DMP** | 新技術を持つスタートアップと随意契約できる国の仕組み。政府調達促進パッケージ（2026年4月）で自治体にも拡大中 | 入札に不利な小さな会社の入口 | 防災庁・自治体への直接提案の根拠 |

### 6-2. 共通の型（7つ）
1. **無料枠で入る**（避難所3か所まで無償、訓練は無償）
2. **初期費ゼロ・定額**（機能全部込み、追加開発なし）
3. **県単位・共同調達**で面を取る（宮城県全35市町村、GovTech東京）
4. **官民共創協議会で無償提供 → 制度化**（Suica、SOCDA）
5. **住民が既に持つものに乗る**（LINE、スーパーアプリ）— 避難所AIは「スマホのブラウザ」がそれ
6. **交付金で初期費、一般財源で保守**（§2）
7. **スタートアップ向け随意契約・DMP** で入札を避ける

### 6-3. 定着しない理由と、それへの答え（リサーチ観点6より）
| 現場の声（デジタル庁 R6 実証の職員） | 避難所AIの答え |
|---|---|
| 「有事の時にしか使わないシステムは使いこなせない」 | 平時の訓練・研修・マニュアル検索で使う（§4-H）。導入の最初の成果物を「訓練で使えた」にする |
| 「システム対応で職員が1人張り付きになる」 | 対話 UI で「進行補助が横にいなくても使える」。避難者が自分のスマホで相談する |
| 「県内の市町で使うシステムが違うと意味がない」 | 標準様式 CSV・EEI 集計で他システムと同じデータを話す。県単位の共同調達を狙う |
| 「発災から3日間は通信不通だったのでアナログと併用が必要」 | そもそもネット無しで動く。紙の名簿も後から取り込める（画像入力・余裕枠） |

### 6-4. 避難所AIの課金案（上の型を当てはめる）
- **無料枠**: 避難所3か所まで・訓練利用は無償（ポケットサイン型）
- **定額**: 自治体単位の年額を避難所数で段階化（4〜10か所／11〜30／31〜）。初期費は交付金（§2）で。既存の相場（初期 11万〜40万円、月 9.3万円〜）より下に置く
- **県単位・共同調達**: 大阪府内の市町村で共同調達 → 単価を下げつつ面を取る
- **自治体負担ゼロ化**: 企業版ふるさと納税と包括連携協定で企業が負担（§5-3）
- **企業・施設は別価格**: 一時滞在施設・介護施設は施設あたり年額（§4-B, C）

## 7. 推奨の組み合わせ（ピッチ用ロードマップ）

## 9. 正直なリスク
- 交付金は**自治体が申請主体**。こちらは自治体の担当者に書類を書かせる立場。担当者が動く理由（訓練で使えた・首長の指示）を先に作る必要がある
- 通信途絶が短い災害では価値が薄い。守りどころは「最初の1〜3週間」「Starlink が来ない小規模・自主避難所」「一時滞在施設」
- 既存ベンダーが自社製品にオフライン AI を足せば差が縮む。F（乗る側に回る）を早めに選ぶ
- 制度の年度・上限は毎年変わる。上の数字は 2026-09-25 時点の公開資料
