### 1.3 「バラバラ」に感じる理由（構造の問題・3 つ）

**(a) 同じ「人」が 6 か所に、違う切り口で出ている**

| 画面 | 何として出るか |
|---|---|
| 名簿 `/staff/roster` | 属性の表（要配慮・伝えたいこと・相談件数の列） |
| 個人ページ `/staff/roster/{id}` | 伝えたいこと・同行者・対応メモ・相談・登録内容 |
| 対応の優先順 `/staff/priority` | 人＋理由＋レベル |
| AI 助手 ② 要配慮者 | 人＋区分（優先順とほぼ同じ集合） |
| 避難者の声 | 発言＋「誰」列 |
| 受付「最近の受付」 | 人＋伝えたいこと |

**(b) 「対応する」が 2 系統ある**: 人への対応は `contacts`（メモ）、発言への対応は `chat_logs.status`（対応済みボタン）。今回メモで相談も閉じるようにしたが、画面には両方のボタンが残っている。

**(c) 分類の語彙が 4 つある**: 要配慮 `care`（7・属性）／伝えたいこと `needs`（10・支援）／声の話題 `topic`（16）／お知らせのカテゴリ（数種）。同じことを別の名前で数えている（例: 「薬」は `needs.medicine`・`care.ILL`・`topic.medical` の 3 か所）。ダッシュボードにはこの 4 つの表が並ぶので「別々の集計」に見える。

加えて画面の問題: タブが **9 本**でデータの出どころ順（名簿／声／AI／お知らせ）に並んでいる。運営者の仕事（誰に対応する・何が足りない・何を伝える・本部へ何を報告する）の順ではない。ダッシュボードは数字タイル 11 枚＋表 4 枚＋一覧で、「今なにをすべきか」が 1 画面で読めない。

## 2. データを 1 本にする（「世帯」を軸に「案件」を束ねる）

### 2.1 結論

**保存の単位は 2 つに絞る**: 「世帯（人）」と、その世帯に起きた「案件」。質問（チャット）を名簿の中に入れるのではなく、**登録時の申告・チャットの相談・職員の対応メモを、同じ形の「案件」として 1 つの表に置く**。名簿（人）と案件（出来事）が 1 対多でつながれば、優先順・声・個人ページ・本部への集計は全部同じ表から出せる。

```
evacuees（世帯・人）  1 ── 多  cases（案件）
                                 ├ source = register  登録時の「伝えたいこと」（needs 1 つにつき 1 件）
                                 ├ source = chat      相談（要望・困りごと・緊急。質問は入れない）
                                 └ source = staff     対面対応のメモ（これが open の案件を閉じる）
```

```sql
CREATE TABLE cases(
  id INTEGER PRIMARY KEY,
  evacuee_id INTEGER,            -- 匿名の相談は NULL
  source TEXT NOT NULL,          -- register / chat / staff
  category TEXT NOT NULL,        -- 統一分類 8 種（§2.2）
  level INTEGER NOT NULL,        -- 5〜1（priority のレベル表をここで確定させる）
  text TEXT,                     -- 申告の表示名・発言の本文・メモ
  lang TEXT,
  status TEXT NOT NULL,          -- open / done
  created_at TEXT NOT NULL, handled_at TEXT,
  chat_log_id INTEGER            -- chat 由来なら元の発言
);
```

- 登録・更新時: `needs` から `register` の案件を作り直す（消えた申告は閉じる、増えた申告は開く）
- チャット: `kind` が要望／困りごと／緊急の発言だけ案件にする（`voices.classify` の結果をそのまま使う）。質問は案件にせず `chat_logs` の統計に残す（お知らせの材料）
- 対面対応のメモ: `staff` の案件（done）を 1 件足し、その世帯の open の案件を全部 done にする（いまの `add_contact` と同じ振る舞い）
- `priority.items()` ＝ `cases WHERE status='open'` を世帯で束ねる。`breakdown().needs`・EEI の `needs`・`priority` も同じ表から。**個人ページ・避難者の声・優先順が同じ行を見る**ようになり、「対応済み」の操作も 1 つになる
- 要配慮 `care`・75 歳以上は**属性**なので案件にしない（名簿の絞り込みと集計に使う）。優先順に「理由」として添えるのはいまのまま
- 既存 DB は起動時に `evacuees.needs`・`chat_logs`・`contacts` から埋め直す（`voices.backfill()` と同じ方式）

### 2.2 分類を 1 つの語彙にする（8 種）

`needs`（10）・`topic`（16）・お知らせのカテゴリを、この 8 種に**写像**する（元の細かい値は残す。画面と集計はこの 8 種で揃える）:

| 分類 | 伝えたいこと（needs） | 声の話題（topic） | 要配慮（属性・参考） |
|---|---|---|---|
| 医療 | 透析・酸素・薬・診察 | medical | MED・ILL |
| 介助・移動 | 移動の手助け | staff（一部） | NUR・DIS |
| 乳幼児・妊産婦 | 粉ミルク・おむつ | baby | INF・PRG |
| 食事・水 | 食事の制限 | food・water | ALG |
| 生活環境 | — | toilet・bath・bedding・env・charge・facility | — |
| 安全・不安 | 不安・眠れない | safety（緊急を含む） | — |
| 家族・安否 | 家族と連絡不通 | family | — |
| 言葉・情報 | 日本語がわからない | info・procedure・pet・other | — |

色も 8 色に固定し、チップ（`tag`・`chip`）の色をこの分類で揃える（いまは kind・topic・need・care で色の付け方が別）。

### 2.3 「1 個のデータセット」として外に出す形

- 本部へ渡す名簿 CSV は 1 人 1 行のまま（標準様式）。列に「**未対応の案件**（分類・レベル・発生時刻）」を足せば、人と案件が 1 枚で渡る
- `eei.json` は集計値だけ（氏名なし）。案件の件数を分類 × レベルで出す

### 2.4 やる時期

提出（16:30）まで 2 時間強。案件表への統合は **2〜3 時間の変更**（表・移行・priority/voices/checkin の書き換え・テスト）なので、**今日は §3 の画面の再編だけ**を勧める。画面の再編はロジックを触らず 60〜90 分。案件表は提出後に入れる（画面の並びは変わらない）。

## 3. タブと画面の再編（仕事の単位で 6 本）

### 3.1 タブ（9 本 → 6 本）

| 新タブ | 問い | 吸収するもの |
|---|---|---|
| **いま** | 誰から対応するか | ダッシュボード。対応の優先順（上位 10）＋ 数字 4 枚（在所人数・未対応の案件・不足している物資の数・答えられなかった質問）＋ 最新のお知らせ 3 件。**それ以外は出さない** |
| **人（名簿）** | この人は誰で、何が要るか | 名簿一覧・個人ページ・**受付（職員の手入力は「＋職員が登録」ボタン）**・**AI 助手②要配慮者**・対応の優先順の全件（絞り込み「対応待ち」として）。絞り込みチップ: 対応待ち／要配慮／日本語以外／想定地区外／退所 |
| **声と伝達** | 何を聞かれ、何を返すか | 避難者の声（話題別・多い質問・発言一覧）＋ **お知らせ**（同じ画面の右側か下）。「お知らせにする」の導線がその場で完結。AI 整理はここ |
| **物資** | 何がどれだけ足りないか | 不足物資の目安・備蓄量の入力（設定から移す）・AI 助手③補足。久保さん（メンター）の「物資のハブ」に当たる独立タブ |
| **本部へ** | 何を報告するか | 内訳（想定地区の割合・日本語以外・支援が要る世帯・受付の方法）・`eei.json` のプレビュー・送信・CSV。**内訳の数字は「本部が知りたい数字」なのでここに置き、「いま」からは外す** |
| **設定** | — | 避難所・Wi-Fi・入口 QR・想定地区・マニュアル取り込み・白紙化・クラウド AI |

AI 助手は**タブから外す**。機能は各画面のボタンに散らす（①マニュアルに聞く → 右上の「マニュアル検索」（全画面共通）／②要配慮者の要約 → 人／③物資の補足 → 物資／④掲示文 → 声と伝達／⑤引継ぎ → いま画面の「引継ぎメモを作る」）。「AI」という入口を作らず、仕事の中に置く。

### 3.2 画面のルール（全タブ共通）

1. **1 画面 1 つの問い**。答えにならない表は置かない（「いま」から要配慮の内訳表・言語・ペット・システム状態を外す。システム状態は設定へ）
2. **数字タイルは 4 枚まで**。赤は「未対応」と「不足」だけに使う
3. **人の行は 1 部品**（レベル色・受付番号・氏名（人数）・分類チップ・待ち時間・「対応メモ →」）。いまの `_priority_rows.html` を名簿一覧・個人ページ・声の「誰」列でも使う。同じ人が同じ見た目で出れば「バラバラ」は消える
4. **分類チップの色は 8 色固定**（§2.2）。種類（質問／要望）は色でなく文字で
5. **対応の操作は 1 つ**: 「対応メモを書く」。発言ごとの「対応済み」ボタンは個人ページからは外し、避難者の声（匿名の相談）にだけ残す
6. 一覧の絞り込みは**チップ**（クリックで切り替え）にし、セレクト 5 個のフォームはやめる
7. 30 秒の自動更新はそのまま。更新時刻を右上に出す
